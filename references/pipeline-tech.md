# 管线技术：逐帧捕获、程序化音频、编码、成本

## 底层链路（全程 Agent 内完成，不开一次剪辑软件）

```
LLM 写 JS/Three.js 单文件 HTML
  → 无头浏览器逐帧捕获（画面逐帧出图）
  → FFmpeg 编码 MP4
```

**确定性来源**：每一秒长什么样由代码写死——可复现（同参数重跑同结果）、可精确改（改哪一秒改哪段代码）。这是与视频模型"抽卡碰运气"的根本分野。

## 分阶段验收（静默版优先）

1. **静默版**：只生成画面，导出逐镜截图
2. **人工逐镜验收**（人眼主战场，模型自述不作数）：
   - 平移/缩放镜头：边缘是否露黑边（安全边距够不够）
   - 装饰元素（星芒/粒子）：是否盖住字幕区与主体
   - 时间轴：同时间段是否画面事件/音频事件重叠
   - 字幕：逐句对读文案，时间轴对齐
3. 全过 → 进入音频阶段；任一不过 → 改代码重跑静默版

**纪律**：一次性要全套（画面+音频+成片）= 出问题返工成本翻倍。分阶段不是慢，是把返工限制在最便宜的阶段。

## 程序化音频（全部代码生成，无采样素材）

| 音频 | 实现 |
|---|---|
| 配音 | MiniMax speech-2.8-hd TTS（key 由用户提供，余额是人的活） |
| 自然音效（水/火/风/雨） | Node 写 DSP 合成：噪声 + 滤波/包络塑形 |
| 乐器（古琴等） | Karplus-Strong 算法合成（拨弦） |
| BGM | 程序化编曲（和弦进行 + 音色合成） |
| 对白闪避 | 侧链压缩：人声出现时自动压低 BGM |

## 成本与档位

| 项 | 数据 |
|---|---|
| Token 消耗 | 一支 2 分钟 2K 片约烧 **1700 万 Token** |
| 额度 | 额度重置期内成本为 0——**重活排在重置窗口后** |
| 分辨率 | 画质不按分辨率加价，1080p 到 2K 自选（以所用模型实际计费为准） |
| 思考档位 | 按任务复杂度选：日常小动效 low/medium；长程任务 high/max（本次长片开 max，跑约 2 小时） |

## 模型选型（本次实操）

MiniMax Code + M3.1-Flash-Preview：原生多模态、1M 上下文、思考深度可调。选型判据：长程任务需要大上下文（整支片子的分镜+代码+迭代记录都在上下文里）、思考深度可调（按档位控制成本）。

## 交付四件套的用途

| 资产 | 用途 |
|---|---|
| index.html | 改一句文案 → 重跑网页版即可，不用从头再来 |
| SRT 字幕 | 可编辑、跨片子复用文案 |
| 分镜截图 | 验收依据 + 回滚锚点（"第 3 镜回到 v2 的样子"） |
| 可复用脚本 | 下次同业务只改参数（捕获/音频/编码脚本） |

**核心**：交付物当资产收，不只收 MP4——MP4 是消费品，四件套是生产资料。
