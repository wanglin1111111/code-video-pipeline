# 需求分流：代码路线 vs 视频模型

## 一句话判据

接到视频需求先问：**"信息密集、要精确控制" 还是 "要真实感、人物、物理运动"？**

- 前者 → **代码路线**（本技能）：每一秒由代码写死，可复现、可精确改
- 后者 → **视频模型**（走人）：真实感、光影质感是生成模型的主场

**别用代码路线硬啃写实镜头，那是拿短板撞别人长板**——双重成本：代码路线做不出写实感，还把本该走视频模型的预算烧在改代码上。

## 判例表

| 需求 | 路线 | 理由 |
|---|---|---|
| 产品功能演示片 | 代码 | 信息密集，UI/文字/动效需精确控制，改一句文案就重跑 |
| 季度数据汇报片（图表动画） | 代码 | 数字、图表、节奏全要精确；可复现，下次只改数据 |
| 动态排版/文字片 | 代码 | 排版即代码的强项 |
| 歌词 MV（风格化画面） | 代码 | 风格化 + 节奏卡点，代码可控 |
| 口播粗剪（字幕+画面编排） | 代码 | 时间轴编排是确定性操作 |
| 品牌片头动画 | 代码 | Logo/字标动效，精确且常改 |
| 真实感人物镜头 | 视频模型 | 代码做不出人脸的"真实" |
| 光影质感/电影感空镜 | 视频模型 | 物理光照是生成模型的长板 |
| 复杂物理运动（流体/布料/碰撞） | 视频模型 | Three.js 物理仿真成本高且不真实 |
| 实拍素材混剪 | 剪辑软件 | 已有素材，不需要生成 |

## 混合策略（一个片子两种路线）

同一支片子可以分段：真实感镜头用视频模型生成 → 信息段落/排版/片头片尾用代码 → 最后剪辑合成。分流是按**镜头**做的，不是按片子。

## 成本直觉（何时值得上代码路线）

| 维度 | 代码路线 | 视频模型 |
|---|---|---|
| 单支成本 | 约 1700 万 Token/2min 2K（额度重置期内可 0） | 按秒计费，真实感镜头贵 |
| 改稿成本 | 改代码重跑，分钟级 | 重抽卡，且结果不可控 |
| 确定性 | 每一秒写死，可复现 | 抽卡碰运气 |
| 迭代次数 | 越高越划算（复用网页版） | 越高越亏（每次重抽） |

判据：**迭代次数多 + 控制要求高 → 代码路线；一次性 + 真实感要求高 → 视频模型。**
