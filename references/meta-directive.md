# 元指令模板（设计与实现分离）

## 两种写法

| 写法 | 形态 | 适用 |
|---|---|---|
| 元提示词 | 让 LLM 先扮演"提示词架构师"，把主题词变成一整套分镜/配色/字幕/文案，再投喂给代码 LLM 执行 | 单次、现场打磨 |
| 元指令 md | 一份 md 文件直接丢给 Agent，只说"四川"或"九寨沟 90 秒"，从设计到成片一口气跑完 | 同业务复用（更懒，推荐） |

**沉淀纪律**：同业务第 2 个片子起必须用元指令 md（只改参数不改结构）。从零重写 = 资产没沉淀。

## 元指令 md 模板（业务版）

```markdown
# <业务名>视频元指令（如：产品功能演示片 / 季度数据汇报片）

## 角色
你是提示词架构师 + 代码实现者。先把下方参数展开成完整分镜设计，
再实现为 Three.js/JS 单文件 HTML 网页动画。设计与实现分离：
先出分镜表给我确认，确认后再生成代码。

## 参数（只改这里）
- 主题词: <四川 / 产品名称 / 季度数据>
- 时长: <90 秒>
- 画幅/分辨率: <16:9, 1080p>
- 风格基调: <国风留白 / 科技蓝 / 数据可视化>
- 配色: <主色/辅色/强调色，可留空由架构师定并列出>
- 字幕: 全程中文字幕，<字体偏好>
- 配音: <TTS 音色，key 由用户提供>

## 输出流程（按序执行，每步等确认）
1. 分镜表：逐段列出 时间段 | 画面 | 字幕文案 | 音效 | BGM
   → 停下等确认
2. 静默版网页动画（只画面，无音频）→ 导出逐镜截图
   → 停下等我逐镜验收
3. 音频：TTS 配音 + 程序化音效/BGM + 侧链压缩对白闪避
   → 停下等试听
4. FFmpeg 编码成片 + 交付四件套（见下）

## 交付四件套（缺一退回）
1. index.html（可双击预览的网页版，改文案可重跑）
2. 成片 MP4 + SRT 字幕
3. 分镜截图（每镜一张）
4. 可复用脚本（逐帧捕获 / 音频合成 / 编码）

## 硬约束
- 每一秒的画面必须代码可复现（禁止随机种子不固定）
- 平移/缩放镜头留安全边距，禁止元素出屏露黑边
- 装饰元素（星芒/粒子）禁止遮挡字幕区与主体
- 时间轴无重叠：同时间段只允许一组画面事件 + 一组音频事件
```

## 使用说明

1. 新建业务版：复制模板，改"业务名"与默认参数
2. 使用：对 Agent 说「用 <业务名>元指令，主题词=XX，时长=YY 秒」
3. 迭代：某次发现的坑（如黑边）→ 写进该 md 的"硬约束"节——**元指令越用越厚，坑不再犯第二次**
4. 版本管理：元指令 md 随仓库走，改约束走 git，可回滚

## 元提示词与元指令的关系

元提示词是"每次现场生成元指令"的做法，元指令 md 是"把元提示词的产物固化下来"。第一次可以用元提示词试结构，跑通 2-3 次后必须固化为 md——此后只改参数，结构不动；每次踩坑把规避写进"硬约束"节，元指令越用越厚，坑不再犯第二次。
