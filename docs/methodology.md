# 用代码模型做视频：AI 写代码，代码出片

> 源材料：「用代码模型做视频」一手实操教程
> 本文为 `code-video-pipeline` 技能的方法论底座；可执行工作流见 `../SKILL.md`。

## 一、奥卡姆剃刀：一句话主题

**AI 不"生成"视频，而是"写"出视频——让大模型写一段 Three.js 网页动画，逐帧录屏，再用 FFmpeg 压成 MP4。**

剥掉所有包装，全文只剩这一句：视频 = 可编程的网页 + 录屏 + 编码。其余的元提示词、音效、BGM、模型选型，都是为了让这条链路能一句话跑通。

## 二、核心提炼

### ① 底层链路

LLM 写 JS/Three.js 单文件 HTML → 无头浏览器逐帧捕获 → FFmpeg 编码 MP4，全程在 Agent 里完成，不开一次剪辑软件。

### ② 确定性

每一秒长什么样由代码写死，可复现、可精确改；这是与视频模型"抽卡碰运气"的根本分野。

### ③ 元提示词

让 LLM 先扮演"提示词架构师"，把地名变成一整套分镜、配色、字幕、文案，再投喂给代码 LLM 执行——设计与实现分离。

### ④ 元指令

更懒的写法是一份 md 文件丢给 Agent，只说"四川"或"九寨沟 90秒"，从设计到成片一口气跑完。

### ⑤ 音频程序化

配音用 MiniMax speech-2.8-hd，音效和 BGM 全靠 Node 写 DSP 合成（噪声做水火风雨、Karplus-Strong 做古琴），再用侧链压缩做对白闪避。

### ⑥ 成本结构

一支 2 分钟 2K 片约烧 1700 万 Token，额度重置期内成本为 0；关键是画质不按分辨率加价，1080p 到 2K 自选。

### ⑦ 模型选型

MiniMax Code + M3.1-Flash-Preview（原生多模态、1M 上下文、思考深度可调）；思考档位按任务复杂度选，本次长程任务开 max，跑了约 2 小时。

### ⑧ 适用边界

产品宣传片、产品演示、动态排版、歌词 MV、口播粗剪——够用；真实感、光影质感、复杂物理运动——目前不靠谱。

### ⑨ 人的作用

提供 TTS key、逐镜截图验收（平移露黑边、星芒盖屏这类 bug 靠人眼挑），以及处理 key 余额、时间轴重叠、ffmpeg 兼容等脏活。

## 三、未来行动指南：怎么塞进你的工作流

### 第一步：加一道分流判断

接到视频需求，先问一句——这个片子是"信息密集、要精确控制"，还是"要真实感、人物、物理运动"？前者走代码路线，后者老实走视频模型。别用代码路线硬啃写实镜头，那是拿短板撞别人长板。

### 第二步：沉淀你自己的元指令

别每次从零写提示词。把这篇文章的思路抽成一份你业务场景的元指令 md（比如"产品功能演示片"版、"季度数据汇报片"版），一次打磨、长期复用，以后只改参数不改结构。

### 第三步：分阶段验收，别一次梭哈

先让它出静默版（只要画面），逐镜看截图确认没问题，再下令"加音效、BGM、TTS 配音"。一次性要全套，出问题返工成本翻倍。

### 第四步：把交付物当资产收，不只收 MP4

要求 Agent 一并交付：可双击预览的 index.html、SRT 字幕、分镜截图、可复用脚本。以后改一句文案，重跑网页版即可，不用从头再来。

### 第五步：额度与档位管理

日常小动效用 low/medium 档快速出；长片才开 high/max。盯住额度重置窗口，把重活排在重置后。

## 一句话收尾

**你以后做视频，核心动作从"剪"变成了"写规格 + 验收"——这才是这条路线真正改工作流的地方。**
